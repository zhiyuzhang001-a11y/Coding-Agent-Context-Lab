# Smart Read：动态路标与上下文导航设计

最后更新：2026-08-15

本设计的长期边界、统一指标与功能准入规则见 `LONG_TERM_CONSTRAINTS.md`。后续扩展必须先通过其中的“开发前五问”，再进入实现与 benchmark。

## 核心定义

Smart Read 不是简单压缩文件的读取器，而是面向大型代码库的动态路标系统。它通过少量高价值标记持续缩小搜索空间，在有限 token 和时间预算下，选择最有可能减少不确定性并推进任务的下一段上下文。

它优化的不是单次读取长度，而是 Agent 从任务描述到获得充分修改证据所经过的完整探索路径。产品本质是 `Context Routing / Context Navigation`，不是逐文件摘要。

## 设计原则

1. 只有能显著降低未来搜索空间的节点，才值得成为高价值路标。
2. 使用稀疏、可验证、可局部失效的事实，不为每个节点生成大段自然语言摘要。
3. 维护稳定的基础地图，并按当前任务动态调整相关区域的分辨率。
4. 探索阶段可以返回压缩证据；编辑前必须展开并读取真实目标实现及必要关系。
5. 同时度量返回 token、完整会话 token、工具轮次、延迟与答案质量。
6. Serena、Codebase-Memory、Git、AST 和 LSP 都是数据源，不是产品架构本身。

## 四类路标

### 结构标记（Structural Marker）

描述节点是什么：模块职责、类、函数、接口、签名和关键数据结构。优先由 AST、Tree-sitter 或 LSP 生成；文件内容哈希变化时局部失效。

### 关系标记（Relational Marker）

描述节点连接到哪里：包含、调用、依赖、继承、实现、测试以及必要的数据流关系。关系必须保留来源和置信度，不能把静态推测伪装成运行时事实。

### 历史标记（Historical Marker）

记录近期修改、相关 Bug、Commit、测试结果和高频变更区域。源码变化不一定使历史失效，但旧记录应随时间和代码距离降低权重。

### 决策标记（Decision Marker）

记录关键设计决策、约束、被否决方案和原因。至少区分 `confirmed_decision`、`historical_decision`、`agent_hypothesis` 与 `rejected_approach`，并保存证据来源，避免模型猜测污染长期事实。

## 路标数据契约

路标主要保存紧凑事实与证据指针，而不是源码正文或长摘要：

```text
Marker
├── identity：仓库、文件、符号、类型、行号
├── role：可选的一句话职责
├── edges：关系类型、目标和方向
├── evidence：源码位置、文件哈希、commit、测试或文档
├── freshness：生成时间、版本和失效条件
├── confidence：来源类型与可信度
├── base_value：长期结构价值
└── expansion_cost：展开预计需要的 token 与时间
```

标记不保存完整源码。Agent 需要确认时，根据 `evidence` 定位真实代码。

## 动态价值与读取优先级

路标价值分为稳定价值与任务价值：

```text
BaseValue(node)
  = 结构中心性
  + 公共接口重要性
  + 变更/故障历史
  + 设计约束重要性

TaskValue(node, task)
  = 语义相关性
  + 与已知目标的图距离
  + 对当前假设的验证能力
  + 预计信息增益

ReadPriority
  = (BaseValue + TaskValue) × Confidence
    ÷ (TokenCost + LatencyCost + StalenessRisk)
```

第一版不追求精确数学模型。各分量必须可解释，并记录最终节点为何被选中。相比单纯中心性，“该节点能消除多少当前不确定性”更重要。

## 任务探索状态

导航器维护短期任务状态，以避免重复读取并决定下一步：

```text
Task State
├── 当前目标
├── 已确认事实及证据
├── 待验证假设
├── 已读取节点与分辨率
├── 尚未覆盖的关键关系
├── 当前风险
└── 剩余 token / 时间预算
```

完整循环是：

```text
任务状态
→ 找出最大不确定性
→ 选择单位成本信息增益最高的节点
→ 返回最小充分证据
→ 更新状态
→ 继续、展开或停止
```

## 动态分辨率

每个节点可按需要逐级展开：

1. 路标身份与评分理由。
2. 签名、职责和直接关系。
3. 目标实现片段与关键调用路径。
4. 完整符号、必要相邻代码和测试。
5. 仅在确有必要时读取完整文件或更宽子图。

例如“修复搜索排序”任务会提高 Retrieval、Ranking 和 Score 区域的密度；认证、UI 和部署只保留低分辨率信息，除非新证据使它们相关。

## 质量保护和停止规则

进入编辑前至少确认：

- 已读取目标符号的完整真实实现；
- 已覆盖必要的直接调用者、被调用者和公共接口；
- 已定位相关测试、配置和关键数据结构；
- 所用路标与当前文件哈希一致；
- 已显式标记低置信度或未覆盖关系。

满足以下条件时可以停止探索：已有证据能解释问题，关键假设已验证，修改边界明确，目标实现和测试已覆盖；或下一次读取的预计信息增益低于阈值，需要把预算留给编辑和验证。

## 目标架构

```text
代码、Git、测试、文档
        ↓
Marker Providers
AST / Tree-sitter / LSP / Serena / Codebase-Memory
        ↓
Sparse Navigation Map
稀疏节点、关系、证据、版本和成本
        ↓
Task Navigator
任务状态、不确定性、价值排序和停止规则
        ↓
Context Bundler
在预算内返回最小充分证据
        ↓
Agent 编辑与测试
        ↓
结果回写为历史或经过确认的决策标记
```

## 与当前实现的关系

已经完成的是导航系统的读取基础设施：

- 工具输出审计与大读取候选检测；
- 小文件全文、大文件按符号/查询/概要分流；
- 多符号批量读取和硬 token 预算；
- 结构元数据缓存、内容哈希失效和重复读取统计；
- Serena 原生符号与引用后端的可行性验证。

统一路标契约、持久目录和 SQLite v1 schema 已在阶段 1.5 完成；M2a 已把 Python 仓库事实增量写入 Marker/Edge 地图，并提供预算化可解释 Top-K。尚未完成的是：任务探索状态、信息增益/语义排序、调用与数据流关系、历史/决策标记，以及编辑前质量门。

## 分阶段实施

### M2a：Sparse Navigation Map v0（已完成）

- [x] 定义版本化 Marker/Edge schema 和 Provider 契约。
- [x] 复用现有 Python AST 和内容哈希生成结构节点、包含关系与导入关系。
- [x] 使用增量更新，只重建内容哈希变化的文件。
- [x] 提供按查询、符号和 token 预算返回 Top-K 路标的本地命令。
- [x] 返回评分分解、证据位置和预计展开成本，不生成大段 AI 摘要。
- [x] 用 Serena 仓库完成 B014：精确符号首次定位载荷相对原生文件探索基线减少约 89.5%；该数字不代表完整会话 input。

### M2b：Task Navigator v0（已完成）

- [x] 保存已见、已选、已展开、已验证节点、待验证假设与剩余预算。
- [x] 以 Marker、证据哈希和区域避免重复展开同一证据。
- [x] 实现反馈驱动且可解释的下一节点选择和枚举化停止规则。
- [x] 固定无标识符任务基准中 3/3 找准目标，2/3 比静态 Top-K 少一次展开。

M2b v0 的完成定义以 `PROJECT_PLAN.md` 八项验收标准为准。预算只覆盖 Navigator 可控制的地图载荷和证据展开，不冒充 Codex 整个会话用量；证据去重使用 Marker、文件证据哈希与区域联合身份，并保留哈希变化、截断和显式强制读取三个例外。

真实 Serena 探针表明，反馈循环只能沿已有证据产生的新调用名、路径和结构邻居推进；当目标需要从继承标记跳到集合处理逻辑时，仅有 contains/imports 不够。M2c 因此先补继承、调用/引用关系，再比较外部 Provider，而不是继续放大词法权重。

### M2c：关系后端比较（已完成 v0）

- 将 Serena 与 Codebase-Memory 映射到统一 Marker/Edge schema。
- 比较索引成本、查询延迟、返回 token、覆盖率和失效行为。
- 达不到端到端质量和至少 20% input 改善的后端不进入核心路径。

M2c 不以 Edge 数量作为完成指标，而以 `PROJECT_PLAN.md` 十项验收标准为准：关系必须正确、稀疏、可增量失效并受预算控制；Navigator 必须实际利用关系减少真实任务断路和错误停止。高价值 reference 使用明确白名单，动态或无法解析的关系必须降低置信度，避免把同名和反射猜测写成事实。

当前 v0 已加入 `inherits`、仓库内直接 `calls` 与白名单 `references`，并把无法解析的外部/歧义名称保存在独立低置信度表，不参与高置信图传播。关系排序区分方向：优先寻找“谁调用/引用当前相关节点”，模块父节点弱于类父节点；Agent 判定无关后，该节点自动抽取出的名称也失效。B016 的 5 个真实任务中错误停止由 3 降为 2，B015 已沿关系链到达 `ToolSet.apply`。

统一报告同时暴露能力边界：内置 AST 参与自然语言导航；Serena 当前只完成已知路径和符号下的精确取证，因此其 5/5 不能与导航正确率直接比较；Codebase-Memory CLI 未安装时明确跳过。M2d 要解决剩余语义候选失败并消除 Serena 的 oracle 提示。

### M3：历史、决策与质量门

- 接入 Git、测试和经过确认的项目记录。
- 建立证据来源、置信度和时间衰减规则。
- 在编辑前检查完整目标实现、必要关系和测试覆盖。

## 当前决策

先实现自己的路标契约和 M2a，不立即把任何上游项目设为核心。这样可以复用当前成果，也能让 Serena、Codebase-Memory 或未来后端以可替换 Provider 的形式接入。
